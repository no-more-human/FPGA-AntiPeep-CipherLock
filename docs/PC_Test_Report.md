- Python 3.12.10；本机可导入 OpenCV 5.0.0（含 face）、PyTorch 2.14.1+cpu、Ultralytics、PySerial、Pillow、Tkinter。
- 25 项 unittest 全部通过：虚位密码/胁迫优先、锁定超时、P 下紧急输入、改密旧密验证/拒绝/回执/超时、敏感日志隔离、人脸结果时效、防窥滞回、摄像头恢复同步、串口分包/粘包/异常帧、PySerial loop:// 真实回环、JPEG/AVI 编解码、中文路径、证据附件合并及录像过期清理。
- GUI 模拟模式可启动并自动正常关闭；通过 Tk 控件尺寸检查确认在本机 1536×960 桌面下主要区域和底部状态栏均可布局。最终默认窗口 1180×880。
- 原 owner 的三张照片成功检测、载入并训练 LBPH，标签映射为 owner。属于训练数据检查，不是独立准确率评估。
- 原始照片端到端分析：01.jpg 得到 1 人体/1 人脸、身份 owner，约 750 ms；02.jpg 和 03.jpg 各 2 人体/2 人脸，约 500/469 ms。输入为原始照片分辨率，与实际摄像头 640×480 不同。照片没有导出或上传。
- 本地 YOLOv8n 实际加载成功。640×480 空白图、推理输入 imgsz=320、CPU 线程数 4 时，初次完整分析约 8203 ms，随后三次约 62、63、62 ms，均检测为零人体/零人脸。这个小样本仅证明模型可运行，不代表真人场景性能或准确率。

## 实物验收建议

1. 普通密码前后混入数字，确认 U、绿灯、开锁动作、日志和照片一致。
2. 胁迫密码及双密码串确认只发 D；现场无异常提示，安保查看器收到报警。
3. 三次错误后 L；P/锁定中仍保留胁迫通道；T 回报后恢复人脸请求资格。
4. 多人持续触发 P、恢复触发 S；短暂遮挡不频繁切换。普通 R 仍由 FPGA 做最终准入判断。
5. 拔插串口和摄像头，确认不会重放旧 R 或改密请求。
6. 旧密码错误/两类密码相同/回执丢失时不能显示修改成功；修改完成后在实体键盘核验新旧密码。
