# 视觉上位机与 FPGA 对接约定

核对基线：main 的 f1e7783（DAY6硬件组）。这是接口约定和待办清单，不是下位机实现证明。

## 当前工程实际情况

rtl/top.v 尚未引出 UART_RX/UART_TX，也未实例化 UART 收发模块。safe_fsm 没有 P/S/R 输入，已有 duress_alarm 仍是粘滞电平。当前密码缓冲上限六位，尚非 README 所描述的 16 位滑窗；常规密码可通过键盘修改，DURESS_PWD 为参数。不能直接声称主分支已完成虚位密码、视觉挂起或 PC 改密。

PC 新目录 pc/ 已实现下面的收发和模拟。请 FPGA 组接线、实例化 UART 并挂接状态机后联合验收。

## 基础协议 v1：兼容已有文档

115200，8 数据位，无校验，1 停止位，ASCII 单字节，无换行。TX/RX 交叉并共地，电平按开发板接口要求核对。

| 方向 | 字节 | PC 行为 / FPGA 待实现 |
| --- | --- | --- |
| PC→FPGA | S 0x53 | 恢复防窥显示与常规输入。不得触发开锁或解除试错锁定。 |
| PC→FPGA | P 0x50 | 防窥请求；常规输入挂起或遮挡显示，保留胁迫通道。 |
| PC→FPGA | R 0x52 | 请求开锁；FPGA 仍应自行拒绝试错锁定/不允许的状态。执行成功回 U。 |
| FPGA→PC | U 0x55 | 正常开锁，记录并抓拍。 |
| FPGA→PC | L 0x4C | 连续试错锁定，记录并五次计划抓拍、录像。 |
| FPGA→PC | D 0x44 | 胁迫开锁，现场与 U 表现相同，安保侧记录真实报警。 |
| FPGA→PC | A 0x41 | 门未关超时，记录并录像。 |

PC 不为每帧重复发送 P/S，只在视觉切换、摄像头异常/恢复和串口重连时同步。旧协议没有 ACK、校验或握手，因此“串口已打开”仅代表操作系统打开了端口，不能证明 FPGA 正常。“R 已发送”不能显示为“开锁成功”。

不要混入 ASCII 调试句子：例如 DEBUG 内的 D/U 会被旧协议当作事件。调试输出另用串口或升级成完整帧协议。串口噪声也可能导致假事件，这是 v1 的限制。

建议在 FPGA 加入“视觉 P 的通信失效处理”：PC 退出或连线拔掉后不能永远冻住键盘，且不能解除本地试错锁定。当前 v1 没有心跳，PC 不会凭空发送一个未定义的心跳字节，具体超时与扩展心跳需双方另行约定。

## 可选事件扩展：FPGA 组确认实现后启用发送

| 字节 | 含义 |
| --- | --- |
| E | 单次密码错误。PC 不从 L 反推三条具体错误记录。 |
| K | 锁舌已闭锁（不要把它等同于门磁已经吸合）。 |
| T | 本地试错锁定计时结束，恢复可操作状态。 |
| C | 手动紧急报警事件。与物理 C 键不是同一个概念。 |

注意当前键盘 C 已用于提前闭锁/清屏，不能在不改设计的情况下同时宣称它是求救键。若采用截图中的 C 求救想法，需双方重新定义按键（如长按 D），并保证现场声光与普通操作相同。PC 已预留 C 事件接收，但现有 FPGA 不会自动发出它。

## 密码修改扩展 v2 提案：默认关闭

v1 无法传密码。现提供 PC 可运行的 @JSON 换行帧作为可选方案；需要 FPGA 组先接受并实现解析，或双方改成更适合 RTL 的固定长度二进制帧。单字节模式下绝不发送扩展帧。

格式：ASCII @（0x40）+ JSON UTF-8 + LF（0x0A），JSON 最大 1024 字节。PC 发出的 JSON 用 ASCII 转义编码。接收解析器能处理跨包与粘包；@ 帧内的 U/L/D 不会被当作事件。错误或超长帧丢弃到换行，之后恢复。

请求示例（仅演示值）：

~~~json
{"type":"request","id":"12ab34cd56ef","op":"password_change","kind":"normal","old":"123456","new":"112233"}
~~~

kind 可为 normal 或 duress。old 始终是当前常规密码。成功响应：

~~~json
{"type":"ack","id":"12ab34cd56ef","ok":true}
~~~

拒绝响应：

~~~json
{"type":"ack","id":"12ab34cd56ef","ok":false,"reason":"auth_failed"}
~~~

只有写入成功后才能 ACK true；错误密码、两类密码相同、长度非法、锁定/挂起等情况必须拒绝。身份校验失败也应计入试错限制。PC 等待 5 秒，超时结果未知，不自动重发改密或 R；重连也不重放旧命令。请求 ID 只关联回执，尚无 FPGA 持久化去重保证。密码通过本地串口明文传输，该协议没有加密/消息认证。

## 优先级：双方必须统一

1. 胁迫密码匹配优先于常规密码；输入同时包含两者时只上报 D。
2. 防窥 P、试错锁定期间也要有专门的胁迫输入通道。完全吞掉所有按键就无法检测胁迫密码，需由 FPGA 修改状态机。
3. 胁迫开锁的舵机、绿灯、语音与普通开锁一致；不得使用现场报警音。
4. S 只改变视觉防窥状态，不重置密码、错误计数、胁迫记录或本地锁定。
5. FPGA 独立执行密码验证、锁定和驱动。PC 断开后仍应能进行实体密码操作。

以上是拟采用的产品行为，模拟器已按此实现；不是对 f1e7783 RTL 行为的描述。

## FPGA 组最小待办

- 引出 UART 并实现 115200 8-N-1 收发；将收发引脚加入顶层及约束，接线以实际板卡为准。
- 接收 S/P/R，控制器明确拒绝不允许的 R。
- 用开锁上升沿发 U；胁迫优先发 D，避免先 U 后 D 误记两次。
- duress_alarm 取上升沿发一次事件，避免粘滞高电平持续刷屏；解锁和清警逻辑分开。
- 锁定起点发 L，门磁超时沿发 A；建议增加 E/K/T。
- 补齐 6–16 位滑窗匹配、胁迫优先和挂起时的紧急输入通道。
- 决定远程改密帧格式及两类密码存储，完成后才启用 extended_protocol。
- 联合测试断线、连续多事件、摄像头丢失、含双密码输入、超长输入和改密超时。
